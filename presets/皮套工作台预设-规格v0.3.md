# 皮套工作台预设 · 规格 v0.3

> 与 workbench 定位的关系：本预设演示"预设 = 纯声明 + 环节编排 + 数据契约 + 审核门 + 路由"，完全遵守 ADR-0001（工作台纯展示层、不承载业务逻辑）与 PRD 四条硬边界（纯 JSON/YAML 声明、原件唯一真相、翻译不了不提前设计、复杂逻辑在 Agent 内部小循环）。

## 一句话定位

**把"接单做 Live2D 皮套"翻译成一条可编排的环节流水线：Agent 通过四类通道产出候选成品，每环节人工审核门放行，数据契约连接全部工具，路由机制按环境/质量/成本择优。**

## 核心设计（五要素）

1. **环节化**：E0-E8，每环节有产出契约（成品定义）与人工审核门；返工可定位到环节。
2. **通道化**：Agent 不直接做美术，只通过 软件 API / MCP / CLI·本地推理 / GUI 自动化 四类通道触达工具。
3. **契约先行**：图像 / 项目 / 发布 / 驱动 四层数据契约是环节间连接器，工具吃吐同一契约即可替换。
4. **审核门**：每环节之间人工审核（艺术产出不合格不进下一步，效率不是目标）。
5. **路由**：候选工具池 + 路由键 + 策略 + 回退链；择优靠每单记录积累。

## 环节规格总表（颗粒度走查版）

| 环节 | 具体操作 | 内部逻辑 | 产出内容 | 通道 | 人审要点 |
|---|---|---|---|---|---|
| E0 输入 | 接需求、收素材、定交付规格 | 需求规格化（什么算完成）+ 资产库建档 | 需求卡 + 素材包 | 资产库 ptr（CLI） | 素材可拆层性、规格完整 |
| E1 定妆 | 写 prompt → 文生图 API → 选稿 | 风格规范资产 → API → 候选 | 定稿 PNG（≥2048、透明底） | 文生图 API | 对称性、尺寸、商用许可 |
| E2 拆层 | 定稿图 → See-Through 推理 | SDXL+LayerDiff 语义分割 + Marigold 深度 + inpaint 补遮挡 | 23 层语义 PSD | CLI/本地推理 | 部件清单核对、补全质量 |
| E3 补修 | 部件重组 + 补画分片 + 规范命名 | 语义层 → Live2D 可动部件"翻译" | 规范修复 PSD | PS API v2 + 人工 | 可动部件齐、无伪影 |
| E4 入编辑器 | GUI 自动导入 → 触发 5.1 AI deformer → 检查骨架 | Native GUI Adapter 菜单自动化 + Cubism 官方 AI | .cmo3（deformer 树） | GUI 自动化 | deformer 树结构 |
| E5 绑参 | 绑标准参数 + keyform + 表情/口型 | Agent 生成参数表（CSV/JSON）→ 人工在 Cubism 导入/精修 → API 驱动验证 | 参数化 .cmo3 | CSV 通道 + Editor API + 人工 | 参数范围、表情、口型 |
| E6 物理动作 | 配置物理 + 生成基础动作 | MCP configure_physics / generate_motions + 官方 AI 摇摆 | .physics3 + .motion3 | MCP | 手感、动作清单 |
| E7 导出 | 导出 .moc3 发布包 | GUI Adapter export 菜单自动化 + API 事件监听 | 发布包 | GUI 自动化 + API | 包完整性、引用正确 |
| E8 验收 | VTS 加载 → 摄像头试跑 → 打包交付 | VTS API 加载冒烟 + 人全权验收 | 交付包 + 验收报告 | VTS API | 全链路、兼容性 |

## 数据契约（四层）

| 契约 | 格式 | 连接 |
|---|---|---|
| ① 图像契约 | PNG-alpha / PSD 层结构 | 文生图 ↔ See-Through ↔ PS |
| ② 项目契约 | .cmo3（JSON 可读写）+ 参数 CSV | Cubism 编辑器 ↔ 外部 API ↔ CSV 导入 ↔ MCP |
| ③ 发布契约 | .model3.json + .moc3 + .physics3 + .motion3 | 模型包 ↔ VTS ↔ 游戏引擎 |
| ④ 驱动契约 | PARAM 映射表（追踪 → 参数） | OpenSeeFace ↔ VTS ↔ 模型 |

## 通道与工具映射（E5 已深挖确认）

| 通道 | 环节 | 工具 | 能力边界（文档确认） |
|---|---|---|---|
| API | E1/E3/E8 | 文生图 API / PS API v2 / VTS API（8001） | 各接口文档即为契约 |
| API | E5 | Cubism Editor 外部集成 API（22033） | **只读+写参数值 + 感知导出/模式事件；参数为 0.5s 临时缓冲，不落盘，不能创建参数/keyform/deformer** |
| CSV | E5 | Cubism [建模]→[模型参数一括设置]→CSV 导入/导出 | **批量设置参数（默认值/范围），Agent 生成 CSV、人一键导入——E5 半自动主通道** |
| MCP | E4/E6 | Live2D Automation（GUI Adapter + 9 工具） | 产 mock 中间包非成品；GUI 驱动靠窗口标题/菜单路径，需校准 |
| CLI/本地 | E0/E2 | 资产库 ptr / See-Through | 本地推理需 GPU（ROCm/DirectML/云端见环境路由） |

### 附录：Cubism 外部集成 API 完整命令清单（2025-08-26 版）

**指令**：RegisterPlugin · GetIsApproval · GetParameterValues(0.9.1 含物理/动画) · SetParameterValues(0.9.1 可选动画模型轨道) · GetParameters(1.0.1 含 Keyform 值) · GetParameterGroups · GetDocuments · GetDocument · GetCurrentDocumentUID · GetCurrentModelUID · GetCurrentEditMode(Physics/Modeling/Animation/MeshEdit/FormAnimation) · SetGlobalVersion · ClearParameterValues · GetPhysicsInfo · SendCubismLog
**事件**：NotifyMocFileExported(0.9.3 含相关文件列表) · NotifyPhysicsFileExported · NotifyMotionFileExported · NotifyMotionSyncFileExported · NotifyChangeEditMode
**粒度结论**：读写参数 + 事件感知，无建模命令（不能创建参数/keyform/deformer/网格）。E5 的 Agent 角色 = 材料生产者（CSV/JSON 参数表）+ 驱动验证者（Set 值→读回→检查响应），建模动作在编辑器内（人工 + 5.1 AI + 模板）。

## 审核门与人介入清单

| 环节 | 人审什么 | 常见翻车点 |
|---|---|---|
| E0 | 素材可拆层性（正面/站姿/单角色/背景干净） | 客户素材是动态姿势/大透视 → 报废 |
| E1 | 对称性、画布尺寸、商用许可 | SD 假透明底、左右不对称 |
| E2 | 部件清单核对、遮挡补全质量 | 丢部件（帽/眼）、头发整片、补全伪影 |
| E3 | 可动部件齐（前发分片/眼睑/口腔/舌头）、无伪影 | 语义层≠部件层，重组工作量最大 |
| E4 | deformer 树结构 | GUI 自动化第一次大概率失败（窗口标题/对话框需校准） |
| E5 | 参数范围、表情自然、口型准确 | CSV 导入后需逐项确认；API 只能驱动验证 |
| E6 | 物理不穿模、动作自然 | MCP 仅 4 种基础动作，定制动作必须人工 |
| E7 | 包完整性、引用正确 | 导出菜单路径版本相关 |
| E8 | 全链路功能、兼容性 | **参数名不匹配→表情静默失效（最大坑）** |

## 路由机制

- **路由键**：① 输入特征（图复杂度/部件数）② 质量要求（交付线）③ 成本约束 ④ 隐私合规（素材能否外传→本地 or 云端）⑤ 环境（显卡型号/Cubism 版本）⑥ 工具健康度（每单记录积累）
- **策略**：规则路由（硬约束 if-then）→ 评分路由（权重打分）→ 实测路由（小样本试跑）；起步只用规则 + 回退链
- **AMD 环境实例**：E2 拆层——卡在官方 ROCm 支持列表（RX 9000/7900 系、Ryzen AI Max）且隐私敏感 → 本地 ROCm；否则 → 魔搭在线/商业 SaaS/租云卡；老卡（RDNA2）→ DirectML 兜底或云端
- **回退链**：每环节候选工具池排序，主选失败/产出不合格 → 备选 → 最后兜底"人工"

## 三个新资产定义（挂载到资产库）

1. **可拆层性检查表**（text 品类）：E0 进门判断清单——正面站姿？单角色？背景干净？可对称？左右手可分离？输出 pass/fail + 回炉建议。
2. **部件映射表**（text 品类）：语义层 → Live2D 可动部件重组规则——头发语义层 → 前发/后发/侧发分片规则；眼睛 → 眼睑/瞳孔/高光；嘴 → 口腔/舌头。一次建，每单复用（E2→E3 翻译层）。
3. **参数映射表 + 参数 CSV 模板**（text/csv 品类）：模型 PARAM ↔ VTS 默认参数名对照 + 可导入 Cubism 的 CSV 模板（E5 半自动通道 + E8 交付必备防静默失败）。

## 输出契约（成品定义）

可交付模型包 = .model3.json + .moc3 + 纹理 + .physics3.json + .motion3.json + PSD 源文件 + 参数映射表 + 验收报告。Agent 保证格式完整、文件齐全、VTS 可加载；质量验收全部由人决定。

## 单点测试计划（打点，不打全流程）

1. **台阶 0（零安装）**：魔搭在线 demo 跑一张真实定妆图 → 看拆层 PSD 质量 → 回答"AI 拆层能不能进交付线 + E3 补修工作量"
2. **台阶 1（本地）**：按显卡型号部署 See-Through（ROCm / DirectML / 云端）→ 隐私单可用
3. **E5 验证**：生成参数 CSV → Cubism 导入 → API Set/Get 驱动验证 → 确认 CSV 覆盖范围（关键帧/默认值）
4. **E4/E7 GUI 校准**：真实 Windows 环境校准窗口标题/对话框路径/菜单序列（放最后，校准密集 + 烧 token）
