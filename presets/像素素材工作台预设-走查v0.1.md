# 像素素材工作台预设 · 走查 v0.1

> 对称于皮套工作台（E0-E8），同一"环节化 + 通道化 + 契约 + 审核门 + 路由"框架。核心差异：皮套是**参数化/结构式**（运行时驱动），像素是**帧序列/生成式**（引擎播放）——产物格式、消费方、审核重点不同，但上游（概念→定妆→部件→动作清单）共用同一资产库。

## 一句话定位

**把"接单做像素卡通风游戏素材"（定妆图 → 动作帧 → 精灵图集）翻译成一条可编排流水线：AI 生成候选帧 → 每环节人工审核门 → 图集直出引擎格式。**

## 双轨对应（人类像素画师 × AI 工作台）

| 人类流程 | AI 工作台 |
|---|---|
| 需求沟通（角色/动作清单/尺寸/调色板） | P0 输入 · 需求规格化 |
| 画概念/定妆草稿 | P1 定妆生成（文生图 API） |
| 像素化精绘（线稿→上色→调色板锁定） | P2 像素化（风格迁移锁定 palette） |
| 逐帧动画（关键帧+中间帧） | P3 帧动画生成（单图出发生成） |
| 修帧（锚点/细节一致性） | P4 精修（Aseprite + 人工） |
| 方向/状态集（4/8 向、技能动作） | P5 方向/状态集 |
| 图集打包（sprite sheet + JSON/plist） | P6 图集打包（CLI 直出引擎格式） |
| 引擎测试（Unity/Godot 导入试跑） | P7 引擎集成冒烟 |
| 交付 | P8 验收交付 |

## 环节走查表（颗粒度）

| 环节 | 具体操作 | 内部逻辑 | 产出内容 | 通道 | 人审要点 |
|---|---|---|---|---|---|
| P0 输入 | 接需求、定动作清单/尺寸/调色板约束 | 需求规格化 + 建档 | 需求卡 + 素材包 | 资产库 ptr | 规格完整（动作数/尺寸/色板） |
| P1 定妆 | 文生图出角色定妆 | 风格规范资产 → API → 候选 | 定稿 PNG（统一画布） | 文生图 API | 角色识别、风格符合 |
| P2 像素化 | 像素化 + 调色板锁定 | 风格迁移（PixelLab/SpriteFlow/本地模型） | 像素定妆 PNG | API / 本地 | **色板锁定（越界即废）**、像素细节 |
| P3 帧动画 | 从单图生成 idle/walk/attack 帧序列 | PixelLab skeleton / AnimateDiff / sprite SaaS | 帧序列（多方向候选） | API / MCP / 本地 | **帧间一致性**（帽子/武器 morph）、循环 |
| P4 精修 | 修锚点抖动、细节一致性 | Aseprite Lua 脚本批处理 + 人工 | 干净帧序列 | CLI（Lua）+ 人工 | 逐帧看循环、锚点固定 |
| P5 方向/状态集 | 4/8 向旋转、技能动作包 | PixelLab 已产品化（rotation/tileset） | 全方向帧集 | API | 方向统一、透视正确 |
| P6 图集打包 | sprite sheet + JSON/plist + 引擎格式 | Aseprite CLI / SpriteFlow 导出 | 图集 + 元数据 | CLI | **格式对应引擎**（Unity meta/Godot tres/Phaser json） |
| P7 引擎冒烟 | 导入引擎试跑动画 | 引擎加载检查 | 冒烟结果 | 引擎/脚本 | 帧名、锚点、动画控制器 |
| P8 验收交付 | 引擎播放全检 + 客户试跑 | 人全权验收 | 交付包 + 验收报告 | — | 全动作、无缝循环、兼容 |

## 关键风险（走查发现）

1. **帧间一致性（最痛）**：帽子消失/剑变木勺/角色 morph——2026 年 AI sprite 工具已改善但未根除；P3→P4 是"翻译鸿沟"（AI 帧序列 → 引擎可用的干净帧），工作量集中在 P4。
2. **调色板锁定**：像素风格硬约束（PICO-8/Endesga 32 等），AI 生成常越界 → P2 必须强制 palette，P4 校验。
3. **尺寸/网格精度**：像素画是精确网格，AI 生成位置不精准 → 需 Aseprite 后处理（对齐网格/整数缩放）。
4. **walk cycle 无缝循环**：循环帧是硬要求，AI 生成的首尾帧常不闭合 → 人工/脚本修补。
5. **图集格式差异**：Unity（.meta+动画控制器）/ Godot（.tres）/ Phaser（JSON）格式不同 → P6 按目标引擎路由。
6. **商用许可**：SaaS 生成素材的商用权需逐工具确认（SpriteBrew AGPL 注意传染）。

## 与皮套工作台的对称/差异

| 维度 | 皮套（结构式） | 像素（生成式） |
|---|---|---|
| 产物 | .cmo3/.moc3 参数化模型 | sprite sheet + JSON 帧序列 |
| 翻译鸿沟 | E2→E3 语义层→可动部件层 | P3→P4 AI 帧→干净帧 |
| AI 成熟度 | 拆层半自动、绑定人工为主 | 生成已产品化、一致性待修 |
| 审核重点 | 变形器意图、物理手感 | 帧一致性、色板、循环 |
| Agent 自动占比 | 中（生成/拆层/物理动作） | 高（生成/像素化/动画/打包） |
